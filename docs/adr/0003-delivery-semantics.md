# Delivery semantics: strictly-newer resume, loss-only gap ledger, uniform grain path, daemon-owned archive

How the daemon survives crashes, reboots and long outages without double-counting or silent holes. **Resume**: within a session, `reqwest-eventsource` re-sends `Last-Event-ID` on every reconnect (the WMF 15-minute kill is the normal path — proven by 8 reconnects in the soak); on boot, the daemon resumes from the durable cursor via `since=` (strictly newer). The cursor and the SSE id are the same kind of thing (WMF ids are timestamp-based, multi-DC), so there is no arbitration problem — boot uses the cursor, sessions use the crate. **The millisecond seam**: an event sharing the exact millisecond of the last applied event could be skipped by a strictly-newer resume, but only if a crash lands precisely between two such events (~1–2% of ms boundaries at ~30 ev/s) — expected loss ≈ zero events per reboot, and the 6-hour raw window makes any drift detectable and re-derivable. Overlapping resume was rejected: it double-counts ~30 events per reboot unless every counter gains per-event dedup — heavier machinery for a smaller risk. **Gaps** mean *permanently lost data only*: downtime inside the replay window (7–31 days; 6 days used as the conservative threshold) is replayed and never recorded. One detector: on the first event after boot, if it jumps more than 6 days past the cursor, a gap row is written (`cursor_ts → first event ts`, cause `retention-exceeded`). Routine reboots never produce rows. **Rollup path**: uniform across grains — every flush upserts the same deltas into the open minute, hour and day buckets (totals rows, with in-memory sketch + estimate), plus per-wiki counter rows at hour/day grain aggregated batch-locally; late events land in their correct (old) bucket automatically, and no bucket-close state machine exists. **Archive**: the daemon itself writes every event's full JSON to hourly `.ndjson.gz` files under `/var/lib/wikistream/archive/` (30-day retention, cleaned on rotation) — full-fidelity history starts with ingestion, not after. **Clock**: the VM is NTP-synchronized; timestamps are trusted. **Counting seam with the ledger**: empty flushes write no ledger rows; the ledger's unique `last_event_id` remains the replay tripwire.
